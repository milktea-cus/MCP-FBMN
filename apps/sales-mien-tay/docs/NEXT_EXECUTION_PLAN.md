## P1: login + identity + multi-territory authorization
1. Integrate Neon Auth pattern (Sales branch or explicitly authorized shared identity; use stable sub); no public signup grants business access. Provision/verify issuer, audience, JWKS, HTTPS trusted origins. Role and enabled state from Sales DB, not self-assigned claims. Create/revoke staff, roles, territory assignments, audit changes.
2. Auth gate in Flutter; remove manual API/token settings and RAM demo from business build. Sign in, sign out, refresh, session expiry, disabled account. No raw JWT/password in IndexedDB/localStorage; use secure server session mechanism on web and secure storage on native where appropriate.
3. GET /me returns identity, role, allowed provinces/districts, permissions and scope revision. Admin assigns multiple provinces/districts in one workflow; enforce uniqueness and explicit replace/revoke. Scope rules apply to list, detail, create, patch, photos, visits, reports, sync. Ordinary sales own records AND active scope; manager views team records within active scope; admin authorized across company. Targets without a province are user-level, not automatically all territories; province-specific targets/forecasts must specify allocation; clarify aggregate calculation.
4. UI province selector contains assigned provinces only; 'Tất cả địa bàn của tôi' is scoped union. Region catalog remains legacy 13 provinces/134 districts. No switching API origin/user in production.
5. Test: one user with two provinces, district-only, overlap/no duplicates, another user with no access, manager restricted scope, transfer/revoke, disabled account, invalid token, missing token. Check record and media access after revocation.

## P2: durable offline-first storage
PWA PHONE **IndexedDB required**, not localStorage, not RAM. Android Flutter native **SQLite** via repository abstraction. Implement platform adapters with consistent domain types and versioned schema. Use IndexedDB transactions and indexes; test mobile Chrome Android and installed standalone. App shell caching separately via service worker; avoid caching authenticated API responses in shared caches. Do not cache or store raw session secrets/passwords.
- Stores: account-scoped metadata/scope version, customer records, survey/target/forecast/visit/dealer/competitor/support records, assigned routes/catalog, pending mutations (UUID client_ref, operation, entity, base version, status, retry), media blobs + metadata (bounded size, upload state), sync cursor/tombstones. User namespace and scope revision mandatory.
- Local write transaction persists business entity + outbox atomically, then shows queued status. Reload/close/reopen, network interruption and retry must preserve pending work. Image Blob persists in IndexedDB and is uploaded after parent record is synced. No base64 in localStorage. Storage quota, quota failure, eviction risk and persistence request: surface status; do not claim browser data can never be evicted.
- Sync pull incremental by cursor and scope revision; push idempotent operations with stable UUID across retries; server validates auth/scope on every operation, version checks/conflicts; deletes via tombstones. Ordered parent/child sync and retries/backoff. Foreground reconnect and manual sync; no dependence on Background Sync support. Handle 401 re-auth, 403 revoked scope, 409 conflict, failed media. Preserve unsynced drafts securely; when logout/revoke, purge or quarantine scoped cached data and do not expose cross-user caches. Offline access bounded by explicit session lease; immediate server revocation applies online, offline device only detects at reconnect/lease expiry. No unsynced business data loss silently.
- Tests: offline create/edit/photo/check-in, close/reopen, retry same UUID, airplane mode, scope change, account switch/logout, storage quota, conflict, reconnect, Android native.
- Server migrations/endpoints for incremental sync, versions, idempotency and tombstones; integration tests actual Worker->Neon and private R2.
